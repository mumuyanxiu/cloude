# Internal contract

## Cloude 2.0 launcher

The package entry point is `electron/launcher.cjs`. The default workspace runs the pinned Paseo Electron client and daemon bundled under `resources/paseo/`. Its provider, browser, terminal and native transport APIs stay within the Paseo desktop bridge. The legacy SSH workspace uses `electron/main.cjs` and its existing `window.workspace` API. Switching workspaces uses an explicit application menu and a process restart. Each mode owns its own windows, IPC and shutdown lifecycle.

Both modes retain the Cloude application ID and established profile root. Paseo daemon state uses a separate `paseo/` directory. Existing `workspace.json`, DPAPI credentials, host keys and `~/.cloude-tasks/` jobs retain their existing reader and runner. The launcher does not resubmit old prompts or copy credentials into Paseo configuration.

The pinned Paseo source, runtime dependencies, local patches and build recipe are recorded with the release. The runtime is built before packaging and shipped locally. Remote Paseo SSH transport requires an already-running compatible daemon and noninteractive OpenSSH authentication.

Updates: getUpdateState(), checkForUpdates(), downloadUpdate() return {status,currentVersion,version,percent,message}. installUpdate() requires a verified downloaded update and no running tasks, connection changes or file operations, then disconnects SSH and drains persistence queues before quitAndInstall(true,true). The renderer disables install while files are dirty. openReleases() opens only the configured public release page. Events include {kind:'update',update:<state>}. Development builds return status unsupported. Installed Windows builds check once after startup; downloads and installation require a user action. autoInstallOnAppQuit is disabled. The update provider is fixed in build metadata, never supplied by the renderer.

App data. CLOUDE_DATA overrides the data directory for isolated tests, with CLOUD_CLAUDE_DATA accepted as a legacy alias. CLOUDE_TEST enables integration test mode, with CLOUD_CLAUDE_TEST accepted as a legacy alias. Cloude packaged builds use the existing `%APPDATA%/Cloud Claude/` profile for upgrade continuity.

Models: getModels({projectPath?}) returns {models:[{value,displayName,description,supportsEffort?,supportedEffortLevels?}],fetchedAt}. Queries use the selected registered project or workspace as cwd, a fresh remote Claude CLI stream-json initialize handshake, and no user message. Hooks, MCP and session persistence are disabled for discovery. The process is terminated after its response, on SSH close, or after a bounded timeout/output limit. Only allowlisted model metadata reaches the renderer, never account details or CLI diagnostics. The renderer refreshes per connection/project, rejects stale responses, offers manual retry and custom IDs, and preserves saved selections missing from the current list with a visible notice. This is the CLI-advertised catalog, not an independent entitlement check.

Desktop preload exposes `window.workspace`, all methods return Promises and reject on errors. Events use onEvent(callback) returning unsubscribe. No local filesystem or shell access from renderer. Remote service is CommonJS RemoteClient class in electron/remote.cjs.

Existing projects: openProject({path}) => {path,name} registers an existing canonical directory on the current connection. File operations permit the workspace and explicitly mounted project roots. Roots are cleared on a new connection and restored from saved projects matching its connectionKey. No project files are copied or created by openProject. listSessions({projectPath}) => {sessions:{sessionId,title,updatedAt}[],warning?}; readSession({projectPath,sessionId}) => {sessionId,title,updatedAt,messages,truncated,notice}. Both run the fixed session-reader.py through Python 3, without starting Claude. Reader access is confined to the matching CLAUDE_CONFIG_DIR/projects/<encoded-project> transcripts, rejects symlink transcripts and requires matching cwd. Lists at most 100 sessions. Text preview follows the visible parent chain, omits sidechains/tools and bounds lines, file size, message count and total display bytes. Import deduplicates by project/sessionId and preserves existing local conversations. The original sessionId is passed through startChat --resume. The transcript format is internal to Claude Code; errors are surfaced rather than fabricating history.

ConnectionConfig: {host, port:number, username, authType:'key'|'password'|'agent', privateKeyPath?, password?, passphrase?, workspace:string, claudePath:string, autoConnect?:boolean, credentialSaved?:boolean}. Default host and username are empty; port 22, workspace ~/claude-workspace, claudePath claude, autoConnect true. Password/passphrase must NEVER persist in plaintext or normal app state. After successful authentication, autoConnect permits OS-encrypted credential storage in the main process, bound to the SSH login identity. credentialSaved is load-time metadata, never an actual secret. Disabling autoConnect and saving clears corresponding saved credentials.

Credentials use direct Windows DPAPI CurrentUser, independent of Chromium's Local State key. Only a fixed PowerShell program appears in process arguments; secrets use stdin/stdout pipes inside the main process boundary, never logs or plaintext files. credentialSaved means the matching record can actually be decrypted. Packaged app instances share a single-instance lock per user-data directory.

Use real SSH/SFTP. No privileged service or permanent daemon installation. Legacy startChat/runCommand are bound to their SSH channels; never claim guaranteed remote process stop on network loss. startPersistentChat explicitly creates a detached, per-task Python supervisor and Claude process. It persists events and pending decisions across SSH disconnects and application restarts; it does not restart tasks after a remote machine reboot or automatically resubmit prompts. Read-only mode uses `--permission-mode plan`; editing uses `--permission-mode acceptEdits`. General Bash is allowed when allowCommands is true, individually prompted when askCommands is true in a persistent editing task, and disallowed otherwise. Plan mode always disallows Bash. Renderer defaults settings.allowCommands to true when absent, persists explicit false, and always sends false in plan mode. Prompts travel on stdin, all remote paths are shell quoted. Preserve Claude login via normal login shell, with PATH including ~/.local/bin; no --bare assumption.

## Desktop bridges and persistent tasks (1.1.0)

Current session lifecycle: `startPersistentChat` keeps one Claude stdio process alive across completed turns when project, session ID, executable, model, effort, mode and runner source version match. Each turn retains a separate job ID, log, pending requests and stop marker. Task status optionally reports `processReused`. Idle processes exit after one hour without sending keepalive prompts; new processes retire excess idle workers to bound resource use. Configuration changes retire incompatible workers before `--resume`; a stopped/dead worker is never silently retried. Starts are serialized per project and reject simultaneous turns for the same session/conversation. Duplicate initialize acknowledgements submit the user prompt only once. Completed jobs cannot stop a later turn on the shared process. Legacy `startChat` retains its per-request SSH lifecycle.

- stageClipboard() and stageDropped(files: File[]) return Attachment[] with opaque ids, display names, kind, size and optional image thumbnails. Native local paths remain in the main process; preload resolves File paths through webUtils. Windows file clipboard and image clipboard are supported. Image staging accepts at most 20 MB. discardAttachments({ids}) releases staged items; uploadAttachments({ids,projectPath}) uploads using the existing guarded upload planner into a unique `.cloude-attachments` batch and returns remote paths. Persisted messages omit thumbnail data. Files and folders are uploaded when the user sends the message, including attachment-only messages.
- readMedia({path}) returns {path,mime,size,dataUrl}; it validates remote scope, file size (20 MB maximum), and PNG/JPEG/GIF/WebP signatures. copyImage({path}) copies decoded PNG pixels to the native clipboard; copyText({text}) writes text. openLocalFile({path}) downloads an allowlisted document/media type into a private local cache and invokes its system application. It does not open arbitrary executable types.
- downloadBundle({path}) presents a native save dialog, traverses one remote directory, downloads into a local staging directory, and produces a ZIP preserving empty directories. It rejects symlinks and caps traversal at 10,000 entries and 1 GB. Partial local archives are removed on failure.
- searchFiles({projectPath,query}) returns {files,truncated}, with up to 80 matches from at most 3,000 scanned entries. It skips common dependency/cache directories and symlinks. File references and selected editor/terminal text become ordinary prompt context.
- openTerminal({jobId,projectPath,cols?,rows?,login?}) opens a persistent PTY running bash, or the fixed Claude auth login command when login is true. resizeTerminal({jobId,cols,rows}) resizes it. writeJob/stopJob and terminal events are shared with the legacy command runner. Renderer xterm handles ANSI, keyboard input and selection. Authentication remains in the CLI/browser flow; credentials are not parsed by the renderer.
- forwardPort({remotePort,localPort?}) returns {id,remotePort,localPort,url}; localPort defaults to an available port. Every tunnel binds only to local 127.0.0.1 and targets remote 127.0.0.1 over SSH. listPorts() lists tunnels; closePort({id}) closes a tunnel and its active sockets. Disconnect closes all tunnels. At most 12 tunnels are active. Connection errors emit {kind:'tunnel',type:'error',data}.
- startPersistentChat({jobId,conversationId,projectPath,prompt,sessionId?,mode,allowCommands?,askCommands?}) returns task identity. listTasks({projectPath}) returns {tasks}; pollTask({projectPath,jobId,cursor}) returns {task,events,cursor,more}, with a byte cursor over complete event records. replyTask({projectPath,jobId,requestId,allow,answers?}) answers one pending CLI control request, preserving the original tool input and optionally adding question answers. stopTask({projectPath,jobId}) requests remote process-group termination. Repeated starts with the same jobId reuse that task rather than rerunning its prompt.
- Remote tasks have states starting/running/waiting/completed/failed/stopped/interrupted, sessionId when available, timestamps and pendingRequests. The fixed Python helper is delivered over SSH; user input is JSON on stdin. Private task data is under `~/.cloude-tasks/<project-hash>/<jobId>/`, with per-user directories and private files. Limits are four active tasks per project, 1 MB per event record and 32 MB per task log. Exceeding limits fails visibly. Task data and uploaded attachments are not automatically deleted.
- settings.durableTasks defaults true; settings.askCommands defaults false; settings.notifications defaults true. Conversation.task stores {jobId,messageId,cursor,finished?}; assistant Message.jobId identifies replay targets. Reconnecting restores the selected unfinished task; the task panel can recover other tasks or replay completed results. Replay clears the target message first to avoid duplicate output. Ordinary tasks and terminals still block update installation; detached tasks can continue while the application restarts.
- notifyTask({jobId,state,title,conversationId,requestId?}) shows a native notification only when the application is unfocused, deduplicates each state/request, and focuses the matching conversation on click via {kind:'navigate',conversationId}. It requires the renderer to poll the task; no notifications are delivered while the application is closed or SSH is disconnected.

The stream-json control protocol is version-sensitive. A real initialization handshake was verified against Claude Code 2.1.318 without a model request. Local automated fixtures cover permission/question replies; no claim is made that every CLI version or external MCP tool behaves identically.

Command suggestions only populate the input. Selection by Tab/Enter or mouse must not submit a chat or shell command. Composition events from an IME must not trigger completion or execution. While terminalJob is active, disable shell suggestions and pass input to the running process. Local slash actions (/help, /clear, /usage, /permissions) are UI operations, not model prompts; /clear preserves old conversations.

Upload batches additionally emit {kind:'transfer',direction:'upload',type:'upload-progress',phase,name?,entriesProcessed?,entriesTotal?,filesCompleted?,filesTotal?,bytesTransferred?,bytesTotal?,fileTransferred?,fileTotal?}. Phases are scanning/checking/confirming/preparing/uploading/committing/verifying/complete. Name is a relative display path, never the local absolute source. Preparation has no estimated percentage. Bytes describe streamed data; completion requires remote replacement and final source checks. The renderer caps progress at 99% until complete, computes average throughput, and displays an inactivity notice after 15 seconds without an event. Existing per-file transfer events remain available.

Browser dev preview MUST clearly say 界面预览 · 未连接设备 and disable genuine backend operations or throw a clear desktop-only error. No fake connections, completions, file saves or downloads. A separate explicit demo mode may use sample content but not simulate device success.
